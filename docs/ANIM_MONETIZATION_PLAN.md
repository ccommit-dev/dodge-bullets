# 애니메이션 마감 · 과금 모델 보강 계획안

작성 2026-09-03. 기준 커밋 2eaa432. 앞선 점검(과금 5종·하단 UI·후속 7종) 이후에도 남은 어색함과 빈 곳을 코드 기준으로 진단하고, 착수 순서와 완료 기준을 정한다.

## 1부. 애니메이션 — 왜 아직 어색한가

### 1.1 현재 구조 (코드 사실)

| 대상 | 아트 | 모션 방식 | 상태 종류 |
|---|---|---|---|
| 영웅 | 캐릭터별 시트 4프레임 | 프레임 교체 (idle 240ms, attack 420ms 클립) | idle · attack |
| 동료 20명 | 단일 프레임 로스터 시트 + 개별 PNG 14장 | CSS transform만 (호흡·전진·타격 흔들림), 무기는 SVG 별도 회전 | 없음 (몸체는 1장) |
| 몬스터·보스 | 단일 PNG | CSS transform (breathe · prepare · strike · lunge · smash · defeat) | 없음 |
| 비트 파티 | 영웅 시트 + 동료 1프레임 | CSS transform (strike · guard · dodge · skill) | 없음 |
| 대장간 | SVG 검 · 견갑 아이콘 | 흔들림 · 불꽃 · 임팩트 텍스트 | 없음 |
| 뽑기 | 동료 1프레임 | 카드 플립 · 등급 발광 | — |

`@keyframes`는 150개가 넘지만 전부 **한 장의 그림을 움직이는** 방식이다. 팔다리가 움직이는 건 영웅뿐이다.

### 1.2 어색한 지점 7가지 (원인 → 관찰)

1. **동료가 미끄러진다.** 전진·타격이 translate/rotate라 다리는 고정된 채 몸이 이동한다. 4프레임 아틀라스(ally-animation-atlas-v1)가 있었으나 사용자 개편에서 단일 프레임으로 되돌아갔다. 원인은 아틀라스 셀 비율(1.5:1) 렌더 문제였고 그 수정은 SpriteArt에 남아 있지 않다.
2. **몬스터가 맞아도 표정이 없다.** 피격은 `monster-hit-recoil`(밀림 + 밝기)뿐이고 피격 프레임이 없다. 보스 처치도 `monster-defeat`(축소·페이드)로 끝난다.
3. **동료 무기와 몸이 따로 논다.** 무기 SVG는 몸체와 다른 앵커·타이밍으로 회전한다. 특히 개별 PNG(루나·볼트·변형 10명)는 구도가 달라 무기 앵커가 어긋난다.
4. **비트 원정의 적이 정지 이미지다.** `beat-training-monster`는 타이탄 보스 PNG를 재사용하고 `beat-enemy-*` 키프레임으로 흔들기만 한다. 리듬 게임인데 적이 박자에 반응하지 않는다.
5. **스킬 연출이 전장 밖 텍스트다.** 스킬 시전은 `flash()` 토스트 + `pushFx` 링 하나. 화상·빙결·고무·가속 버프는 HUD 칩만 바뀌고 전장에는 표시가 없다.
6. **변형 10명은 팔레트 파생이다.** 임시 아트라 실루엣이 원본과 같다. 뽑기 픽업 쇼케이스에서 "새 동료"로 읽히지 않는다.
7. **뽑기 연출이 결과만 보여준다.** 소환 버튼 → 즉시 카드 플립. 기대감을 만드는 사전 연출(소환진·등급 예고 색)이 없다.

### 1.3 수정 계획

원칙: 프레임이 필요한 것(1·2·4)은 **프레임 아틀라스**로, 나머지는 **레이어 이펙트**로 해결한다. 새 원화 의존을 최소화하고, 원화가 오면 파일만 교체되게 경로를 고정한다.

#### A. 동료 4상태 아틀라스 복귀 (1·3 해결) — 2일
- `ally-animation-atlas-v1.png`(6명 × idle/run/attack/hit)와 변형·스킨 아틀라스를 다시 연결한다. 셀 비율 문제는 `.ally-body { width:150%; left:-25% }`로 해결한 이력이 있다(커밋 4ac5aa7).
- 무기 앵커를 **프레임별**로 둔다: `WEAPON_ANCHOR[baseId][state] = {x,y,rot}`. 개별 PNG 동료는 무기를 몸체에 합성한 PNG로 바꾸고 SVG 무기를 끈다(루나·볼트는 이미 무기가 그림에 있다).
- 완료 기준: `scripts/inspect-anim.mjs`의 rest/attack 프레임에서 동료 팔 위치가 달라야 하고, 무기가 손 밖으로 벗어난 동료 0명.

#### B. 몬스터 피격·처치 프레임 (2 해결) — 2일
- 종류 5종 + 보스 5종에 대해 `hit` 1장, `defeat` 1장을 생성한다. 원화가 없으므로 원본 PNG에서 파생: hit는 밝기 반전 + 8° 기울임 + 흰 테두리, defeat는 회색조 + 조각 분해 마스크. `scripts/make-monster-states.mjs`로 자동 생성.
- 보스 처치는 3단계: 경직(0.3s) → 균열 이펙트 → 붕괴 + 골드 분출.
- 완료 기준: 보스 처치 시 화면에 3단계가 순서대로 보이고 `monster-defeat` 단독 페이드가 사라진다.

#### C. 상태 이펙트 레이어 (5 해결) — 1.5일
- 몬스터 위에 `.status-layer`를 두고 버프별 스프라이트를 겹친다: 화상(불꽃 루프), 빙결(얼음 결정 + 청색 톤), 고무(동료 발밑 금색 링), 가속(영웅 잔상).
- 스킬 시전 순간은 슬롯별 컷인: 시동기(검 궤적), 연계(원형 마법진), 마무리(화면 플래시 + 줌 0.06).
- 완료 기준: 버프 6종이 각각 전장에서 구분되고 HUD 칩 없이도 상태를 읽을 수 있다.

#### D. 비트 적 반응 (4 해결) — 1일
- 적을 박자에 동기화한다: 비트마다 `beat-enemy-pulse`(스케일 1.04), PERFECT에 `hit` 프레임(B에서 생성한 것 재사용), DROP에 `stagger`.
- 완료 기준: 판정 결과 4종이 적의 서로 다른 모션으로 보인다.

#### E. 뽑기 사전 연출 (7 해결) — 0.5일
- 버튼 → 소환진(1.2s, 등급 예고 색: 파랑/보라/금은 최종 등급을 숨기고 랜덤 페이크 30%) → 카드 플립.
- 완료 기준: 10연에서 SSR 포함 시 금색 예고가 최소 1회.

#### F. 변형 동료 원화 (6 해결) — 외부 의존
- 필요한 것: 10명 × 4상태 = 40장(또는 1장씩 10장). 파일명은 `public/titans/generated/allies/<id>.png`로 고정돼 있어 교체만 하면 된다.
- 원화 전까지는 A의 아틀라스 복귀로 **동작**은 원본과 같이 살아난다.

우선순위: A → B → C → D → E. 합계 약 7일. F는 병행.

## 2부. 과금 모델 — 무엇이 비어 있나

### 2.1 현재 상품 구조

| 축 | 상품 | 수 | 상태 |
|---|---|---|---|
| ₩ 재화 | 보석 80/450/1,200 | 3 | 어댑터 준비, 스토어 미등록 |
| ₩ 패키지 | 모험가 세트 3종 | 3 | 1회 한정 |
| ₩ 캐릭터 | 흑요석·새벽 | 2 | 패시브 구현됨 |
| ₩ 월정액 | 후원 계약 30일 | 1 | 효과 구현됨 |
| 보석 확률형 | 동료 소환 | 1 | 천장·공시·10연 |
| 보석 확정 | 조각 선택팩·재화 4종·외형 8종·상점 동료 4명 | 17 | |
| 보석 기간 한정 | 이벤트·특별 상점 | 6 | 주간 한도 |

### 2.2 빈 곳 6가지

1. **반복 결제 이유가 월정액 하나다.** 후원 계약(₩5,500)이 유일한 정기 상품이고 시즌 구조가 없다. 30일 뒤 다시 살 이유가 "보석 15/일"뿐이다.
2. **첫 결제 전환 장치가 없다.** 첫 구매 2배·첫 구매 한정 패키지가 없어 ₩1,500 첫 결제의 문턱이 그대로다.
3. **영웅(플레이어)에 쓸 돈이 없다.** 캐릭터 2종 외에 영웅 코스튬·무기 이펙트·전장 테마가 없다. 가장 오래 보는 대상이 가장 팔 것이 적다.
4. **동료 외형이 2종뿐이다.** 스킨은 가렌·레온만 있고 나머지 18명은 살 게 없다. 뽑기로 얻은 SSR에 돈을 더 쓸 통로가 조각팩 하나다.
5. **무과금 보석이 뽑기 1회/8일 수준이다.** 루틴 10 + 출석 130/7일 + 주간 30~40 ≈ 주 100. 천장 60회(6,000)는 무과금에게 1년이다. 뽑기가 "언젠가"가 아니라 "안 됨"으로 읽힌다.
6. **광고 보상형이 없다.** 보상형 광고(가속권 4h·방치 2배)는 무과금의 보석 대체재이자 낮은 ARPU 국가의 주 수익원인데 자리만 있다.

### 2.3 보강 계획

원칙 유지: 확률형은 동료 소환 1종. 나머지는 확정 구매. PvP 없음이므로 "격차 판매"가 아니라 "시간·수집·외형 판매".

#### G. 시즌 패스 (1 해결) — 3일
- 4주 시즌. 무료 트랙 30단 + 유료 트랙(₩7,900). 경험치는 루틴·토벌령·주간 도전 완료로 쌓인다(이미 있는 카운터 재사용: `eventSave`).
- 유료 보상: 시즌 한정 동료 스킨 1종, 무기 이펙트 1종, 보석 600, 조각 선택권 3장. 무료 보상: 보석 150, 강화석, 조각.
- 완료 기준: 시즌 패스 화면·진행 바·구매·수령이 e2e로 검증, 시즌 롤오버 시 미수령 소멸 경고.

#### H. 첫 결제 보너스 + 성장 패키지 사슬 (2 해결) — 1일
- 각 보석팩 첫 구매 시 2배(1회). `claimedRewards`에 `first-double:<id>`로 기록.
- 진행도 트리거 패키지: 지역 개척 시(₩3,900 "개척 축하"), 첫 벽 실패 시(₩5,900 "벽 돌파" — 조각 선택 30 + 가속권), 환생 시(₩12,000 "환생 세트"). 각 1회. 추천 배너(recommend.ts)의 `wall` 톤에 연결.
- 완료 기준: 트리거 3종이 정확히 1회만 노출·구매 가능.

#### I. 영웅 외형 라인 (3 해결) — 2일 + 원화
- 무기 이펙트(스킨과 별개, 검격 궤적 색·잔상) 3종 × 보석 300, 전장 테마(하늘·바닥·파티클) 3종 × 보석 400, 영웅 코스튬 2종 × ₩5,900.
- 무기 이펙트는 C의 상태 이펙트 레이어를 그대로 쓴다.
- 완료 기준: 장착 시 전투·마이페이지·공유 카드 3곳에 보인다.

#### J. 동료 스킨 확장 (4 해결) — 1일 + 원화
- SSR 10명에 스킨 1종씩(보석 300). 원화 전까지는 tint 파생으로 생성(`make-ally-skins.mjs` 확장).
- 픽업 동료의 스킨은 픽업 기간에만 20% 할인 → 뽑기와 외형 구매를 한 동선에 둔다.

#### K. 무과금 보석 경로 재설계 (5 해결) — 1일
- 목표: 무과금 주 300 보석(10연 1회/3주). 출처: 루틴 10→15/일, 토벌령 4종 완료 +10/일, 주간 도전 3종 전부 보석(30/40/50), 원정 일지 잔여 항목 보석화, 시즌 패스 무료 트랙 150.
- 뽑기 픽업 주기를 지역 개척과 분리해 **2주 회전**으로 바꾼다(현재는 진행도 고정). 회전 = 같은 지역 동료 중 2명씩 교대.
- 완료 기준: 밸런스 시뮬에 보석 수입을 추가해 30일 무과금 소환 횟수 ≥ 12회.

#### L. 보상형 광고 (6 해결) — 2일 + SDK
- 자리 3곳: 방치 정산 2배(1일 3회), 가속권 4h(1일 1회), 보스 실패 후 재도전 시간 +10초(1회/보스).
- 광고 제거(₩3,900)는 이 3곳을 **무료로 자동 적용**하는 상품으로 실체화한다.
- 앱인토스 웹뷰에서는 SDK가 없으므로 Capacitor 빌드에서만 노출. 미연동 시 자리 자체를 숨긴다(빈 버튼 금지).

우선순위: K → H → G → L → I → J. 합계 약 10일 + 원화.

### 2.4 예상 효과 (가정 명시)

| 지표 | 현재 | 목표 | 근거 |
|---|---|---|---|
| 무과금 30일 소환 | ~4회 | 12회 | K |
| 첫 결제 전환 | 기준 없음 | 보석팩 첫 구매 2배로 소액 전환 유도 | H |
| 반복 결제 축 | 월정액 1 | 월정액 + 시즌 패스 + 진행 패키지 3 | G·H |
| 외형 상품 수 | 10 | 28 | I·J |

수치는 이 장르의 일반적 범위를 가정한 것이며, 결제 연동 후 2주 데이터로 재조정한다.

### 2.5 리스크

- **확률형 확대 금지.** 시즌 패스·스킨은 전부 확정. 픽업 회전은 풀 구성만 바꾸고 확률·천장은 유지 → 공시 화면 갱신만 필요.
- **광고 SDK는 개인정보 처리방침 변경 유발.** 광고 ID 수집 항목이 추가된다. L 착수 전 방침 개정.
- **아트 병목.** F·I·J는 원화 의존. tint 파생으로 먼저 열고 원화 도착 시 파일 교체하는 방식으로 일정에서 분리한다.
