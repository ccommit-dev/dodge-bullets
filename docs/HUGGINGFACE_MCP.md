# 허깅페이스 MCP 연동 · 모델 생성 가이드 (2026-09-21)

이 저장소의 원화는 지금 **로컬 SDXL**(`art-gen/gen.py`)로 만든다. 허깅페이스 MCP는 그 파이프라인을 대체하는 것이 아니라
**"어떤 모델·스페이스를 쓸지 고르는 단계"**를 대화 안으로 끌어오는 도구다. 둘의 역할을 먼저 나눠 적는다.

| | 로컬 SDXL (`art-gen/`) | 허깅페이스 MCP |
|---|---|---|
| 하는 일 | 실제 이미지 생성·컷아웃·배치 | 모델/데이터셋/논문/스페이스 **검색**, 문서 조회, Gradio 스페이스 호출 |
| 화풍 고정 | IP-Adapter 참조 + 고정 시드 + STYLE/NEG 상수 | 없음 (스페이스마다 다름) |
| 비용·속도 | 내 GPU, 512px 4시드 ≈ 2분 | 원격 큐 대기, 무료 티어는 순번 |
| 오프라인 | 가중치 받은 뒤에는 가능 | 불가 (사내망 프록시 영향) |

결론부터: **게임에 들어갈 원화는 계속 로컬로 뽑는다.** 허깅페이스 MCP는 ① 새 체크포인트/LoRA를 찾을 때,
② 특정 작업(업스케일·배경 제거·포즈 추출)에 쓸 스페이스를 찾을 때, ③ 모델 카드·문서를 읽을 때 쓴다.

---

## 1. 연결

서버 주소는 `https://huggingface.co/mcp` 다. 이 세션에서 커넥터 카드를 띄워 뒀으니 **Connect** 를 누르면 된다.
(카드가 안 보이면: 데스크톱 앱 → Connectors → 디렉터리에서 "Hugging Face" 검색)

연결하면 계정 토큰으로 인증된다. 토큰은 huggingface.co → Settings → Access Tokens 에서 만든다.

- 공개 모델 검색만 할 거면 **read** 권한이면 충분하다.
- Gradio 스페이스를 호출하려면 스페이스마다 별도 허용이 필요할 수 있다(비공개/게이트 모델).

> **사내망 주의**: 이 환경은 프록시가 `curl` 을 막는다([[corp-proxy-blocks-curl]] 참고). MCP 는 앱이 직접 HTTPS 로 붙으므로
> 보통 동작하지만, 연결이 실패하면 프록시 예외가 필요한 케이스다. `huggingface.co` 와 `*.hf.space` 두 도메인을 확인한다.

## 2. 붙으면 생기는 도구

디렉터리에 등록된 목록 기준:

| 도구 | 쓰임 |
|---|---|
| `hf_whoami` | 토큰이 제대로 붙었는지 확인 (첫 호출로 연결 점검) |
| `model_search` / `model_details` | 체크포인트·LoRA 찾기, 라이선스·태그·파일 목록 확인 |
| `dataset_search` / `dataset_details` | 학습·평가용 데이터셋 |
| `space_search` | Gradio 스페이스(= 돌아가는 데모) 찾기 |
| `paper_search` | 논문 |
| `hf_doc_search` | diffusers·transformers 문서 검색 |

여기에 스페이스를 활성화하면 그 스페이스의 추론 함수가 도구로 추가된다(예: FLUX.1-schnell 스페이스를 켜면
`gr..._infer` 형태의 생성 도구가 붙는다). **어떤 스페이스가 붙는지는 계정 설정에 달려 있으므로, 연결한 뒤
`hf_whoami` → `space_search` 순으로 실제 목록을 확인하고 쓴다.**

## 3. 이 프로젝트에서의 실제 사용 절차

### 3-1. 새 모델을 후보로 올릴 때

1. `model_search` 로 후보를 찾는다 — 이 프로젝트가 쓰는 조건:
   - 태그 `text-to-image`, base `SDXL` 또는 `FLUX`
   - **라이선스 확인 필수** — 상용 게임에 넣을 수 있는지 (`openrail++`, `apache-2.0` 은 가능, `cc-by-nc` 계열은 불가)
   - IP-Adapter 호환 여부 (화풍 앵커를 그대로 쓰려면 SDXL 계열이어야 한다)
2. `model_details` 로 파일 목록을 본다. `.safetensors` 단일 파일이면 `art-gen/hf-cache/` 에 받아
   `gen.py` 의 `load_pipe()` 가 가리키는 경로만 바꿔 A/B 한다.
3. 같은 시드·같은 프롬프트로 기존 몬스터/동료를 한 장씩 다시 뽑아 **화풍이 기존 로스터와 섞이는지**만 본다.
   섞이지 않으면 아무리 품질이 좋아도 쓰지 않는다 — 한 화면에 같이 서는 그림이다.

### 3-2. 후처리 스페이스를 쓸 때

지금 파이프라인의 약한 고리는 두 군데다.

- **컷아웃**: `rembg` 가 가끔 흰 후광을 남긴다(이번 고블린 4시드 중 2장이 그랬다).
  `space_search "background removal"` 로 BiRefNet / RMBG-2.0 계열 스페이스를 찾아 비교할 만하다.
- **업스케일**: 512px 로 뽑아 쓰는데 보스처럼 크게 나오는 원화는 여유가 없다.
  `space_search "upscale"` → Real-ESRGAN / SUPIR 계열.

두 경우 모두 **원본은 로컬에서 뽑고 후처리만 원격**으로 보내는 형태라, 화풍 고정은 그대로 유지된다.

### 3-3. 쓰지 않는 쪽

- 게임에 들어갈 최종 원화를 스페이스에서 바로 뽑는 것 — 시드·IP-Adapter·네거티브를 우리가 통제 못 해서
  `art-gen/ref/` 화풍 앵커가 안 걸린다. 한 장만 봐도 로스터에서 튄다.
- 대량 배치 — 무료 티어 큐 때문에 4시드가 몇 분씩 걸린다. 로컬이 훨씬 빠르다.

## 4. 연결 점검 순서

```
1) hf_whoami          → 계정 이름이 나오면 인증 OK
2) model_search       → "sdxl" 로 아무 검색, 결과가 오면 네트워크 OK
3) space_search       → 쓰려는 스페이스가 목록에 있는지
4) (스페이스 도구)     → 활성화한 스페이스의 추론 도구가 보이는지
```

1에서 막히면 토큰, 2에서 막히면 프록시, 3~4에서 막히면 스페이스 권한 문제다.

```bash

```

아무 것도 안 하고 끝난다(로그에 "Python" 한 줄만 남는다).
